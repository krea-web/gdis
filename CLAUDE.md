## Architecture notes for future sessions

### Booking flow (post-WhatsApp refactor)
```
homepage fleet card / hub page CTA
    ↓ (link with ?vehicle=<slug>)
/prenotaora?vehicle=fiat-panda  (Astro page, BookingFlow island)
    ↓ Step 1: VehicleSelection (auto-selects from ?vehicle query)
    ↓ Step 2: DateSelection
    ↓ Step 3: PickupDropoffStep + summary card
    ↓ tap CTA → buildWhatsAppRequest(lang, {...})
wa.me/393520459150?text=<pre-filled IT/EN/DE/FR message>
    ↓
manual handling by owner on WhatsApp (availability, kasko, delivery cost)
    ↓
contract drafted offline via Telegram + OCR workflow (separate task)
```

### Content layer
- Per-location data: `src/content/locations/*.json` (7 files) with full IT default + `i18n.{en,de,fr}` override blocks
- Per-vehicle data: `src/content/fleet/*.json` (4 files), same pattern
- Zod schema in `src/content/config.ts` — when adding new fields, update both top-level and `locationI18nFields` partial
- 4 dynamic location templates (`noleggio-auto-a-[slug].astro` + 3 i18n) merge `base` + `tr` (translation override) for each prop
- New `intro` field (from SEO Phase 5) renders as keyword-rich above-fold paragraph on all 28 location pages

### Schema strategy
- `src/lib/siteSchema.ts` is the single source of truth: `Organization`, `LocalBusiness`+`AutoRental`, `Service`, `FAQPage`(speakable), `HowTo` (3-step booking flow post-refactor), `BreadcrumbList`, `Product`/`Car`
- `@id` is **page-scoped** for hub LocalBusiness blocks (`${canonical}#localbusiness`) — IMPORTANT: do NOT reuse the IT URL on EN/DE/FR pages (that was the Critical bug fixed in commit `3dd90f6`)
- `paymentAccepted`, `currenciesAccepted`, `priceRange €50–€250`, `knowsLanguage`, `serviceArea` GeoCircle 60km — all global via `buildLocalBusinessSchema()`

### i18n
- `src/i18n/utils.ts` exports `useTranslations(lang)`, `getRoute(name, lang)`, `getFleetPath`, `getLocationPath`
- Routes: `booking` = `/prenotaora` IT, `/en/book-now`, `/de/jetzt-buchen`, `/fr/reserver`
- `useTranslations` supports `{varName}` interpolation in templates (e.g. `t("booking.request.pickup.deliverySummary", { address })`)

### Performance
- Self-hosted Inter + Space Grotesk via `@fontsource-variable/*` (commit `cff3377`)
- LCP preload on hero images via `BaseLayout.lcpImage` prop
- Vercel Edge CDN with `Cache-Control` immutable on hashed assets, `max-age=0, must-revalidate` on HTML

## Important gotchas / footguns

- **NEVER `git push --force` on `astro-migration`** — PR #1 is the long-running merge target for the whole Astro migration. Force-push loses the migration work plus all SEO+WhatsApp commits
- **NEVER commit `.env`** (gitignored, but worth re-checking before any squash/cherry-pick)
- **When editing `src/content/{locations,fleet}/*.json`, validate Zod schema** — Astro build will fail loudly if any required field is missing. The `DeepRequired<T>` cast in dynamic templates hides this from TS check
- **Astro content collections cache** — if you change `src/content/config.ts` schema, delete `.astro/` and re-run build
- **When adding new pages**, update `astro.config.mjs` `LOC_ALTERNATES` to keep hreflang clusters complete — missing entries silently break multilingual SEO
- **CSP `'unsafe-inline'` is load-bearing** — don't drop it until inline scripts are migrated to nonces, otherwise IntersectionObserver reveal animations and GTM consent stub will silently fail in production but work locally
- **Vehicle slug matchers in `VehicleSelection.tsx`**: regex-based — if you rename a vehicle in DB (make/model), update `SLUG_VEHICLE_MATCHERS` constant
- **Date locale**: BookingFlow uses `date-fns/locale` (`it`, `enUS`, `de`, `fr`). When adding a 5th language, register the locale here too
